# Text engine: encoding, control codes, script VM, pointers

Addresses: CPU `$bb:aaaa` (LoROM, FastROM `$80+` mirrors) and file offsets.

## Where the text is

- **All dialogue is one block in bank $83: file 0x1AA38-0x1BE33 (5,115 bytes, 143 strings), CPU $83:AA38-$83:BE32.**
  **verified**: decoded with `tbl/jp.tbl`, roundtrip-exact, every string reached by a script pointer
  (`tests/test_recon.py::test_text_block_roundtrip_and_coverage`). Before it: palette data; after it: the script table.
- ROM-wide scan for other font-encoded strings (runs of valid codes ending in 00, kana-dense) found nothing else that
  reads as Japanese (hits at 0x11xxx and 0x54xxx-0x77xxx decode to kana noise). **verified** by reading the scan.
- Menus, HUD, option screen, GAME OVER / STAGE CLEAR / CONTINUE are English graphics; Japanese graphics text is
  listed in `graphics.md`.

## Encoding (font-cell order, no Shift-JIS)

- Code = glyph index of the dialogue font (`font.md`). One byte `i + 0x10` for glyph i < 0x70; any glyph also as two
  bytes `0x80 | i >> 8, i & 0xFF` (the script uses the two-byte form only for i >= 0x70: 80xx and 81xx).
  Reader: `$83:9D7B` (byte < 0x10 -> control, < 0x80 -> `code - 0x10`, else `word - 0x8000`) -> glyph draw `$83:9F01`.
  **verified**: disassembly + decode of the whole block.
- `tbl/jp.tbl` is generated by `tools/gen_tbl.py` from the glyph list read off the font
  (`tools/font_sheet.py`). Look-alikes fixed by script context: 束 (約束, was 東), 漠 (砂漠, was 漢), 鍾 (鍾乳洞, was 錘);
  々 (odd shape) confirmed by 我々; 減 vs 滅 both exist (手加減 / 滅び). Font has ぼ but no ぽ (script writes ちっぼけ).
- Glyphs 0x00 = full-width space, 0x08 = "…" (one cell; the script writes …… as two). Digits, ＡＢＨＷｃｍ only
  for the profile screens.

## Control codes (bytes 0x00-0x0F, all one byte, no arguments)

Dispatcher `$83:A4E9`: `JSR ($A4F9,x)` with X pushed/pulled, so no handler consumes argument bytes.
**verified** (disassembly).

| Code | tbl | Handler | Effect |
|---|---|---|---|
| 00 | `{end}` | - | end of string |
| 01 | `{page}` | $A51A | newline + wait for button, new box page (sets $7F002D=3) |
| 02, 03 | `{c02}` `{c03}` | $A528 | cursor $2C = code-1 (unused in script) |
| 04-09 | `{c04}`.. | $A530 | JSL $83C2DE with A=0E and a byte from $A551 table (effect/sound; `{c04}` opens two Toutetsu lines) |
| 0A, 0B, 0E, 0F | | $A519 | no-op (RTS) |
| 0C | `{wait}` | $A55D -> $A4A8 | wait (unused in script) |
| 0D | `{n}` | $A561 | newline; after row 3 scrolls/advances |

Cursor: `$7F002C` low nibble = column, bits 4-5 = row (3 rows per box). Text pointer while printing: `$7F0020`;
the reader sets DB = its own bank (`PHK/PLB` at $83:9178), so **text pointers are 16-bit and text must stay in
bank $83** unless the reader is patched.

## Script VM (cutscene dialogue scripts)

- Script table: 87 words at file 0x1BE33 ($83:BE33-$83:BEE0), 0 = unused slot. Scripts follow at $83:BEE1-$83:C2D4.
  `tools/script_vm.py` walks them. **verified**: all 143 text pointers come from it, exactly one per string start.
- Interpreter: current op in `$7F001A`, script pointer `$7F001E`; jump table `$83:8A15` (ops 00-17). Each handler
  reads its arguments (`$83:940D` word, `$83:9427` byte) then fetches the next op (`$83:9443`).

| Op | Args | Meaning (guess unless noted) |
|---|---|---|
| 00 | - | end of script (verified) |
| 01 | word | portraits/speaker pair -> $7F3418 (e.g. 0501 = stage 5 enemy, char 01) |
| 02-06 | word | show text at $83:xxxx (verified); variants = speaker/box placement: 02 hero alone, 03 enemy, 04 hero, 05 enemy reply, 06 Toutetsu |
| 07, 08, 09, 0A, 12, 16 | byte | effects / music / scene setup |
| 0B-0F, 10, 11, 13-15 | - | effects, waits; 0F = close box |
| 17 | word | text pointer for the character profile screens (slots 84-86) |

Slot layout: three slots per scene, one per heroine (op 01 low byte 00 = 波無寿 Hamusu, 01 = 流風 Rufu, 02 = 河意留 Kairu:
**guess** from speech style - ボク / blunt / polite); lines shared between heroines point at the same string.

## Free space for text (candidates, not verified)

- `$83:DB7A-$83:FFFF` (file 0x1DB7A-0x1FFFF, 9,350 bytes of 00) - the only big run in bank $83. With the 5,115-byte
  original block that is ~14.4 KB for English if the text stays in bank $83. Trap-test it before use.
- The header says 2 MB (size byte $0B) but the file is 1.5 MB: banks $B0-$BF could be added. Moving text out of
  bank $83 needs the reader's `PHK/PLB` replaced by a bank load (phase 5).
